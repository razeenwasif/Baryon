# Session to eval plan

The plan doc: https://claude.ai/artifact/NvEbN96ZZ49eZ6kKJtBJ2t (18 Nov). Any request you made in a work session can be saved as an eval task: the request, the project exactly as it was before Fairy started, and a check that says whether a later attempt got it right. Saved tasks run with `scripts/eval.mjs` beside the made-up ones, so the orchestrator, Auto and the role seats are measured on your own work.

## Stages

| Stage | What | State |
|---|---|---|
| 1 | Where a turn started: every work turn records its commit and a patch of what was uncommitted | Built 18 Nov (branch `evals-from-sessions`) |
| 2 | The saved-task world: a git world kind in `evals/runner.mjs`, `--saved` in `scripts/eval.mjs`, the task format in Fairy's data folder | Built 18 Nov (branch `evals-from-sessions`) |
| 3 | Save as eval: the button beside Rewind to here, the card with the suggested check, the check run once on the starting state, Settings → Evals | Built 18 Nov (branch `evals-from-sessions`) |
| 4 | Running from Fairy: one or all from Settings after a card, results beside the original session's, the offer from a chat | Built 18 Nov (branch `evals-from-sessions`) |
| 5 | With the tracker: each eval run recorded as a run | Built 19 Nov (branch `evals-from-sessions`) |

## Stage 1

- **What's taken** (`startState` in `desktop/turn-starts.mjs`), with git and no model call: whether the folder is in git; its commit (none before a first commit), branch and top folder; and what was uncommitted, as `git diff --binary HEAD` (staged and unstaged changes, deletions, binary files) plus each untracked file git doesn't ignore. Over 5 MB in all, or an untracked file over 1 MB, isn't kept, and the reason is: an eval can still start from the commit alone.
- **When.** At the start of `driveWork`, before the turn's first step, for every work turn: sent from the window or the MacBook, a side session's, one Electron started, a turn carried on after sleep. A swarm's build step isn't a request of yours, so it isn't taken. A slow repository holds the turn up for at most 8 seconds; a failure is kept as the reason and never fails the turn.
- **Where** (`TurnStarts`): Fairy's data folder, `turn-starts/<session>/<turn>.json`, one small file per turn, never the project. Older than 90 days, or past 4,000 turns, goes; pruned every 50 writes.
- **Checked.** A real repository with a change, a staged change, a deletion, a binary change, new files and something ignored, rebuilt elsewhere from the commit, the patch and the untracked files alone, matches the folder exactly. 2,392 tests, 4 in `test/turn-starts.test.mjs`.

## Stage 2

- **A saved task** (`evals/saved.mjs`, `cleanSaved`): `id`, `title`, `ask`, `permission` (ask, auto or plan), `tags`, `saved`; `start` (the repository's full path, the commit, and the base64 patch and untracked files from the turn's start, at most 8 MB); `verify` (a command whose exit says pass or fail); `hidden` (files written just before it runs, such as tests the turn wrote, 512 KB at most); `checks` as data: `testsPass`, `checksItsWork`, `changesNothing`, `changesOnly` (paths), `neverRuns` (a pattern) and `says` (a pattern); and `reference` (the session, turn, reply, files changed, seconds, model and tokens the first time). A path that climbs out, an absolute one or one in `.git` is dropped. Kept in Fairy's data folder, `evals/saved/<id>/task.json` (`saveTask`, `loadSaved`), never in the repository.
- **The git world** (`gitWorld` in `evals/runner.mjs`): a shared clone of the repository, which reads its objects and never writes to it, checked out at the commit with its remote removed; the patch applied with `git apply --binary`; the untracked files written; and the dependencies git ignores (such as `node_modules`) copied in as own-branch sessions copy them. A commit that's gone is said and the task skipped, never run on what's there now. Then the same `runWork`, sandbox, hidden files, check command and checks as the made-up tasks. For a real repository the before-and-after snapshot leaves out `.git` and dependency folders and stands a file over 2 MB as its size and hash.
- **From a terminal**: `node scripts/eval.mjs --saved` runs the saved tasks (`--task <id>`, `--tag bugfix`, `--saved-dir` for another folder, `--list --saved`) with every provider, role, split and orchestrator flag as before; a task that can't be read is left out and named. Each result is set beside the session it came from (“the first time: 41s, … on claude-opus-5-5; now …”), and the run is saved with `-saved` in its name for `compare`.
- **Checked.** A task saved by hand from a real repository (a bug committed, a README change and a new file not yet committed) replayed with the scripted provider in the macOS sandbox: the hidden test confirms the start was rebuilt exactly, the fix passes, a turn that doesn't fix it fails, and the repository's status, refs and worktrees are unchanged. The command line lists, runs, filters by tag and saves the run. 2,395 tests, 3 in `test/saved-evals.test.mjs`; the 28 made-up tasks still pass scripted.

## Stage 3

- **The button.** Save as eval sits beside Rewind to here under each of your work requests (`src/app.js`), shown on hover. It works in the work session on screen once its turn has finished.
- **The draft** (`draftEval` in `desktop/eval-saving.mjs`), from what's kept and no model call: the request; where the turn started (stage 1), refused for a turn from before 18 Nov, a folder outside git or one with no commit; the check, suggested as the last test command the turn ran that passed (`node --test`, `npm test`, `pytest`, `cargo test` and the like), with the others offered; the test files the turn wrote or changed (from its rewind checkpoint), offered as hidden files only if they're still as the turn left them; the files it changed; and the first session's reply, time, model and tokens. A work folder below the repository's top is followed: paths become the repository's, and the check runs as `cd '<folder>' && …`.
- **The card** (`src/save-eval.js`): name, the request (edit out anything that leans on earlier turns), the check, the hidden tests to add, “It may change only the files this turn changed”, the kind (the ten kinds Auto-by-task will route by, or not said) and tags.
- **Saving** (`buildTask`, `checkAtStart`, `startVerdict`): the check runs once where the request started, in a throwaway shared clone in the sandbox, with the hidden tests added; a check that already passes there, or doesn't finish in 3 minutes, isn't kept and the card says why. Kept in Fairy's data folder, `evals/saved/<id>/task.json`, and runnable at once with `node scripts/eval.mjs --saved`.
- **Settings → Work sessions → Evals saved from your work** (`src/evals-settings.js`): each saved task's name, repository and commit, kind and tags, what it passes on, and how long the first time took and on which model, with Remove.
- **Calls.** `eval-draft`, `eval-save`, `evals-list` and `eval-remove`, all on the Remote list, so the MacBook's window can save one in a work session on the mini; `eval-save` is a long call. The saved-task format and the git world moved to `desktop/` (`saved-evals.mjs`, `git-world.mjs`), since the packaged app doesn't carry `evals/`; the runner imports them.
- **Checked.** In a test page: the card filled in, a refused save showing why, a good save, and the Evals list. A real repository's turn (a bug, a test written, the fix) drafted, built from choices and checked where it started in the macOS sandbox: with the hidden test it fails there and is kept; with `true` it passes and is refused; the repository is left as it was. 2,402 tests, 6 in `test/eval-saving.test.mjs`.

## Stage 4

- **Run, Run all, Stop** in Settings → Work sessions → Evals saved from your work (`src/evals-settings.js`). Each task shows its last result (passed or failed, time, tokens and model) beside the first time.
- **The card first** (`evals-run` in main): “Run 3 saved evals on <model>?”, the tasks, and what they took the first time (tokens in and out, minutes), which a run spends about again. Nothing starts without Run them; no answer is no. One run at a time.
- **The run** (`runSavedTask` in `desktop/eval-run.mjs`): each task, one at a time in the background, as one work turn on your work sessions provider and model, in its rebuilt start in a throwaway folder, with Fairy's work tools and sandbox in the task's permission (anything it would ask you for is refused, as in `scripts/eval.mjs`); then its hidden files, its check command and its checks, scored by the same checks as the terminal (`desktop/eval-checks.mjs`, now shared: the app doesn't carry `evals/`). A task whose commit has gone is skipped and says why. Progress goes to the window, and the list also reads itself again every 4 s while a run goes on, so the MacBook's window follows it too; the end is a notification (“2 of 3 passed”).
- **Results** (`EvalResults`): each run in Fairy's data folder, `evals/results/<stamp>.json` (the last 200), with the provider, model and each task's result; the list shows the latest for each task.
- **From a chat** (`offer_save_eval`, in the work tools' new `evals` group, offered directly when you say a request went well or badly or to keep it as an eval): it opens the Save as eval card for your previous request in that chat, if the chat is on screen; you choose the check and save it, and nothing is saved unless you do. A request that's still being worked on can't be drafted; an earlier one can, even while the chat works on another.
- **Checked.** A saved task run in the app's way in the macOS sandbox with a scripted turn: the fix passes, no fix fails, a gone commit is skipped, the repository is left as it was. The list with results and a run going on in a test page. 2,406 tests, 4 in `test/eval-run.test.mjs`; the 28 made-up tasks still pass with the shared checks. Not yet: a real run on a model, which spends allowance.

## Stage 5

- **Each run from Fairy is a run in the tracker** (`trackedRun` in `desktop/eval-run.mjs`). When Run or Run all finishes, or is stopped, Fairy keeps it in the run store under Fairy's own `evals` folder, shown in Runs as **Saved evals** (tagged Evals). Its name is the model and the score (“gemini-4-neon-high · 1/2”); its parameters the model, provider, Fairy's version, how many tasks and how many were skipped; its metrics how many passed, the pass rate, the time and tokens in and out, and each task's pass as 1 or 0 (`pass <id>`). So runs on different models or versions sort, filter and compare in Runs' table and charts.
- **Not recorded**: a run from the terminal (`scripts/eval.mjs --saved`), which keeps its own file in `.local-data/evals` for `compare`.
- **Checked.** 2,438 tests; a run's shape and its place under Saved evals in `test/eval-run.test.mjs`. Not yet: a real run on a model.
